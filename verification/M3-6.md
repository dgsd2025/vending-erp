## 坑(each)

1. **`-Dmaven.build.directory` 原本是空转的**:超级 POM 把 build 目录写死 `${project.basedir}/target`,该 -D 参数并不会被引用——M3-5 坑1 的"独立构建目录"其实一直没生效,三张并行票全在共享 backend/target 里互踩(我 test-compile 时正撞上 M3-3 重编译,报一堆 bad class file/NoSuchFile)。**修法(本票落地)**:pom `<properties>` 增 `<maven.build.directory>${project.basedir}/target</maven.build.directory>` 默认值 + `<build><directory>${maven.build.directory}</directory>`,向后兼容(不传=老行为),传了才真正隔离;`help:evaluate -Dexpression=project.build.directory` 验证生效。
2. **事件时序陷阱**:测试里"上月补导销售"若采购入库 bizTime 用今天,CostEngine 按业务时间重放时销售发生在采购**之前** → 无成本池、成本记 null。造历史月数据必须让采购 bizTime 早于销售 bizTime。
3. **同事务里 JdbcTemplate 写 + MyBatis 读 = 一级缓存脏读**:JdbcTemplate UPDATE 不清 MyBatis 一级缓存,同参数的 mapper 查询直接命中旧缓存(lock_diff 清提示断言假失败)。测试内改数据要走 mapper(update 会清缓存),或换参数。
4. **浏览器 pane 是并行会话共享的**:我在 tab-8 截完 p10,下一眼它已被 M3-3 会话导航到 5191 验证台;tab 有上限,关掉一个废弃 tab 再 tabs_create 自己的,别抢别人的 tab。
5. **docker exec mysql 不带 `--default-character-set=utf8mb4` 时,SQL 里的中文字面量(WHERE order_type IN ('正常',…))会被拆字节,查询静默返回 0**——对照 SQL 全部要带该参数(M3-5 坑3 的 SQL 版)。
6. **共享 vend_dev 的结算模式是活的**:curl 轮我把 mode 还原 UNSET,浏览器轮页面却显示 PLATFORM——并行票在同库演练。共享 dev 库的"全局开关"类断言只能取当下快照,不要假设自己是唯一写手。
7. **`已核销结算单区间`只存在于 yc_vend_settlement(period_start/end),而 init.sql 把 lock_diff_note 建在了 yc_vend_settle_bill(应付结算单,无区间概念)**:本票在 V1.0.12 给 yc_vend_settlement 补同名列作为运行时通道(settle_bill 旧列保留,Scenario14 字段在位断言不破),提示写在有区间语义的表上。
