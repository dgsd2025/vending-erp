## 一、逐条修法 / 测试 / 绿否

### ① 盲审 P1-1 · NL 查数逗号连表绕安全闸 —— ✅ 绿

- **修法**:`NlQueryService.enforceSafety` 新增「闸1.0 逗号连表拦截」。用 `FROM_CLAUSE` 正则把 FROM 子句主体抠出(from → 下一个 `where/group/having/order/limit/union/join`/结尾前),**FROM 子句里出现逗号即拒**——强制「单表 或 显式 JOIN 白名单视图」,堵死 `SELECT * FROM v_ai_loss, yc_vend_user` 这类隐式交叉连接(原正则只认 from/join 后第一个表,逗号后的表漏检)。原白名单逐表校验保留。
- **测试**:`AiFamilyTest.nlCommaJoinRejected` —— 逗号连白名单外表(`v_ai_loss, yc_vend_user`)被拒(消息含"逗号连表")+ 逗号连两个白名单视图(`v_ai_loss, v_ai_cash_summary`)也被拒 + 单表仍放行补 LIMIT。
- 文件:`ai/service/NlQueryService.java`

### ② 盲审 P1-2 · 异常 explain 全盘信客户端 —— ✅ 绿

- **修法**:
  - `AnomalyService` 新增 `explainByKey(key, force)`:**只收 key**,服务端 `detect()` 重新侦测定位那条异常,用**服务端自算的 metrics** 起草;找不到 key 抛 `BizException`(不给伪造 key 归因)。原 `explain(Anomaly,...)` 降为内部方法(只接受来自服务端 `detect()` 的对象)。
  - `AiController.anomalyExplain` 入参从 `@RequestBody AnomalyService.Anomaly` 改为 `ExplainReq{ key }`,调用 `explainByKey`。**不再吃客户端 metrics/幂等键**,杜绝"假数字当真归因"与缓存投毒。
  - `ExplainReq` 只声明 `key` 字段(Jackson 默认忽略多余字段)——旧前端仍可发整条异常体,服务端只取 key,**非破坏性**;新前端只发 `{key}`。
- **测试**:`AiFamilyTest.anomalyExplainByKeyServerSide` —— 造真实销量骤变→取 key→`explainByKey` 起草;断言落库 `inputDigest` 含服务端重算的 `prev7dQty/cur7dQty`(真数字)、`confidence_source=computed`;未知 key 抛异常。
- 文件:`ai/service/AnomalyService.java`、`ai/interfaces/AiController.java`
- **⚠️ 前端联动**:explain 端点契约变为 `{key}`(旧整条 body 仍兼容),前端修复票据此调整即可。

### ③ 七律 P1-1 · 置信分写死却称真算 —— ✅ 绿(处置见第二节表)

  - `LlmTransparencyService.detail` 返回体新增 `confidenceSource`,供 🔬 弹窗 Tab③ 据此显示口径(前端票改文案)。
  - 三个原为常量的挂点改**真算**:anomaly 用偏离度、nl 用模板匹配度、ocr(真 key 路径)用字段完备度。
