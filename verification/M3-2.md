## 5. 坑与环境备注(each)

1. **§9.2 样板 2254−351.63≠1911.37**:调研报告数字自相矛盾(见 §0),系统按公式出 1902.37,不硬凑。
2. **op_log.action 长度上限**:红冲连锁说明一度拼进 markRedFlushed 的 reason → op_log.action 截断报错;改为连锁明细由 SettleBillService 单独落 op_log,reason 保持短句。
3. **MyBatis-Plus 置 NULL**:红冲释放抵扣要把 used_settle_bill_id 清空,entity-update 会忽略 null 字段,必须走 LambdaUpdateWrapper.set(...,null)。
4. **并行票共用一个 MySQL 容器**:两个测试 JVM 同时跑 vend_test_regression 时,doc_no 的 COUNT+1 取号在两个未提交事务里各算出 RK-...-001 → uk_doc_no 上 S 锁互等死锁(偶发)。单跑稳定绿;根因是跨进程并发测试同库,非本票代码;长期可把取号改 SELECT ... FOR UPDATE 或号段表(记 backlog)。
5. **vend_dev 是共享 dev 库**:M3-1 验收给 payment:1 留过凭证,导致 curl 步骤⑧首次确认"意外"过门禁——countOf 判定其实正确;写验收剧本时新单复测即可。
6. **8097 后端中途被外部杀掉一次**(21:59 收到 shutdown hook,疑似并行票收尾 pkill 波及):重启后续走;多票并行请按端口精确杀(lsof -ti:8097),别裸 pkill java。
7. **红字冲抵策略**:红字整张带入,本单实结吃不下的整张留给下一单(不拆分),避免半张红字的对账噩梦;deduction 同理(超应结直接拒)。
8. **老单据兼容**:结算单生成不动采购单状态(仍"已确认"),老板复核时才推"待结算"——保证 M1/M2 全部既有用例(含 stockWarehouse 垫底单)零改动通过,回归绿的关键设计取舍。
