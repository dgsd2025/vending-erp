## 二、核心设计口径

### 到期自动回查三分支(用户拍板)
- **① 达标** → 验证通过(任务关闭),`verify_value` 落指标实际值;
- **② 未达** → 未见效升级(`未见效升级` 态,note 提示换招/另立任务),允许加招后再回查;
- **③ 取不到数**(无键/键未注册/本月没盘点/样本太短等) → **需人工判定**,状态不动,`verify_note` 说明为什么。
- 比较方向:`<=`(损耗/带回率/缺货这类越低越好)、`>=`(动销率/符合率越高越好)。

### 指标键注册表(11 键,对接现成 C 指标源)
| 指标键 | 数据源(复用) |
|---|---|
| `stocktake.loss_amount` / `stocktake.match_rate` | stocktake_item(与 lossStats 同口径,offline_exempt 剔除) |
| `replenish.stockout_rate` | slot.current_qty(推算值,权威以后台缺货页为准) |
| `replenish.takeback_rate` | prekit_ticket.takeback_rate(核销时算好,取月均) |
| `purchase.receipt_diff_rate` / `purchase.price_last` / `purchase.price_mom` | doc_head/doc_item(单据即台账,与 PurchasePriceMapper 同口径) |
| `select.sell_through_rate` | sale_record 简版(正常+兑换口径;**M4-1 BI 多维口径上线后换源,键名不变**) |
| `price.change_effect` | price_log + sale_record(调价前后 14 天 A/B 自对照) |
| `money.overdue_payable_count` / `money.diff_pending_count` | MoneyLightsService(复用 M3 aging 灯,不另抄公式) |

> 铁律#7 遵守:数字全由规则引擎/SQL 算,LLM 起草位留 mock(措施建议规则版预填,M4-5 AI 票接真网关时只换文案生成器,键名/入参不变)。

### 盘亏向导第 5 步起草
- 按"有改进空间"的原因(**吞货掉货/过期报损/被盗**)逐原因起草;账错类(录入/盘点错误)、原因不明不起草(前者补账,后者下轮重点盘)。
- 预填:来源=盘点 / 指标=该原因当月损耗额 / 目标=本次损耗减半(≥¥10)/ 验证日=下次月盘(下月 1 日)/ sourceRef=盘点单。
- 预填**不落库**,老板在对话框确认后才逐条 create;`existing` 回显已挂任务防重复起草。

### 六环节看板定级
- 环节灯 = 所有指标里最差的一盏(**worst 口径**:红>黄>绿>灰)。
- **无数据亮灰灯(gray)不亮绿**——没数据 ≠ 健康(缺失=null,不硬编码默认好)。
- 阈值:补货售罄<5%(红)/<2%(黄)、带回率<10%/<5%、采购涨幅>20%红、动销率≥75%(黄线)/<50%红、盘点损耗<¥30(黄)/<¥50(红)、符合率≥98%(黄线)。

## 四、坑 / 记账

1. **MyBatis 注解 SQL 的 `<`/`>` 转义**:非 `<script>` 包裹的 `@Select` 里 `&lt;`/`&gt;` 不会被解码(HTML 实体只在 `<script>` 动态 SQL 内生效),初版 stockoutSlots 等 4 处报语法错。**修法**:纯 @Select 用字面 `<`/`>`(Java 字符串非 XML);仅 `<script>` 内的比较才写实体。
2. **看板"环节灯"= worst 指标**:小样本盘点(1 行且全差异)符合率算 0% 会把盘点环节拉红,即使损耗额本身是黄。这是**正确行为**(符合率是硬指标),测试断言改为在指标级验损耗黄、环节级验 worst 红。
3. **并行票测试互扰**:`bi.BiServiceTest` 曾用 Java 10+ 语法在源级 8 下编译失败,阻塞 `mvn test` 编译全部测试源。临时移出跑测→并行会话已提交可编译新版,未回填旧副本。bi/ai 模块文件严格未碰。
4. **指标"取不到=需人工判定"是特性不是 bug**:本月无盘点→损耗额 null、无采购史→进价 null、调价样本<3天→变化率 null,一律走人工判定分支,绝不编 0 蒙混(铁律#7 + 数据源战略:缺失=null)。
5. **选品动销率现为 sale_record 简版**:M4-1 BI 多维口径并行在做,`select.sell_through_rate` 的 resolver 换源即可,看板/回查/任务表全不动(键名稳定)。
6. **LLM 起草留 mock 位**:盘亏起草的措施建议现为规则版预填(MEASURE_SUGGEST 表),M4-5 AI 票接真网关时 `ai_draft=1`+`llm_call_id` 落库,只换文案生成器。
