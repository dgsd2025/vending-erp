## 0. 设计要点(附录D 落地口径,后续票别改)

- **PLATFORM**:待结算余额 = Σ(sale_record 正常−退款,settlement_id IS NULL,兑换/测试/线下不计)——实时算不落表;
  确认 = ①系统额快照(区间内待回填聚合)②两差对账(漏单差=系统−账单;扣款差=预计(账单−手续费)−实际;
  任一 |差|>±1 元 → 差异挂起红灯)③回填 sale_record.settlement_id(只碰 NULL 行,幂等)
  ④MoneyPostingEvent 两笔:**货款结算 收(毛额=实际到账+手续费,pl_line=不进利润表**——收入已在销售报表
  按 sale_record 确认,虚账划转不再进利润表防双记)+ **平台手续费 支(利润表「平台吃掉多少钱」行)**;
  净入账=实际到账,账户余额永远等于真钱。
- **DIRECT**:结算单变「商户账单核对单」(HD- 前缀),只录 区间+账单额,确认只算漏单差,
  **不落收入流水、不回填**——钱已直连入账,真实到账靠 M3-5 钱盘账户核对对总,避免双记;
  **直连模式销售确认时也不落流水**(同理防双记,核对单只出差异报告)。
- **UNSET**:录入/确认拦(横幅指路);总览出两模式「假设对比预览」各一版参考数,全部标"非正式"。
- 防呆:mode_snap 录入时快照,确认时必须=当前模式(改模式旧单只能作废重录);
  确认用条件更新抢占(待核对→核销中)防双击/并发双过账;凭证门禁前置(不动任何状态就拦)。
- **兑换补贴对冲(Scenario04 收口)**:GET /v1/settlement/exchange-roi = Σ兑换出货成本(cost_amount,
  NULL 行不计另报"N 行成本待补" §13.2-6)vs Σ厂家补贴确认额(deduction 非作废,按 待抵扣/已抵扣 拆列)。

## 5. 坑 each

1. **测试事务里"确认抢占"与门禁顺序**:凭证门禁若放在条件更新(待核对→核销中)之后,@Transactional 测试里
   BizException 不真回滚参与事务,状态停"核销中"卡死后续断言 → 门禁**前置**(不动任何状态就拦),
   生产语义也更好(被拦=什么都没发生)。
2. **并行票共用 vend_dev 且实时互踩**:浏览器真走时 M3-6 票把 settle-mode 从 UNSET↔PLATFORM 来回切、
   还把共享浏览器标签导航到自己的 5192 —— 表现为"点录入弹出 UNSET 拦截横幅/标签被换页"。
   应对:每步操作前重查模式、当场重设;多票并行请各开各的 tab,别 navigate 别人的。
3. **浏览器 pane 截图合成 bug**:长页面截图上半屏出黑块且帧滞后,coordinate 点击极易点偏 →
   把验证卡挪到 /money-lab 页首 + 关键断言全部走 read_page/JS(getBoundingClientRect 取真坐标再物理点击),
   el-select 选项对合成事件免疫,必须"物理点开 + 轮询可见 popper 后派发完整 pointer 事件序列"。
4. **FinReportTest 2 失败非本票**:M3-6 当轮新增(V1.0.12 22:23 落库,写本票验收时对方仍在开发),
   其用例 jdbc 直插 settlement 行不经过本票代码;本票迁移只加列。若收口时仍红,归 M3-6 收。
5. **两差与真钱解耦**:扣款差≠0 时流水仍按"毛额=实际+手续费"落 —— 账户余额永远等于真钱,
   未解释的差额只在 diff_arrival 上挂红灯等复核,不去"凑平"流水(规则引擎出数字,七律#7)。
6. **模式切换的单据一致性**:靠 mode_snap 快照 + 确认时比对,改模式后旧待核对单只能作废重录;
   已核销单的逆向(退回填+退流水)属红冲连锁范畴,本票明确不做(报错文案已指路)。
