## ④ 坑(每条一句话)

1. **uk_user_role 唯一键含 user_id**:SSO 前大家 user_id=0 会撞键(两个不同人同角色插不进)——按人名 hash 生成稳定伪 ID(同名同 ID),接 SSO 后换真实 ID。
2. **并行票 target/ 争用**:同一棵树上并行票在编译,`mvn spring-boot:run` 会撞上 target/classes 被清("找不到 MockLlmService.class"/"Unable to find main class")——8091 验证改为 `mvn package` 后把 jar 拷到 scratchpad 独立 `java -jar`。
3. **配人前物化的实例是"未配人"**:实例生成时解析责任人,之后才配 user_role 的话已有实例不会自动带人——加 backfillAssignees(仅未完成、未转派过的回填),今日视图自动愈合。
4. **weekView 先物化后标逾期的顺序**:补物化的过去日若先取数再 markOverdue,会以"待办"示人——已改为全部物化→标逾期→跑校验→再取数。
5. **selectCount 返回 Long**:`assertEquals(0, longVal)` 是 Integer vs Long 恒不等,断言必须用 0L。
6. **flyway 版本号占位**:并行票各按票号占段(V1.0.3 replenish / V1.0.6 task)+ `out-of-order: true`,低版本后到也能补跑,vend_dev 实测两票迁移共存 success。
7. **盘点/补货建议是并行模块**:校验 SQL 全写成只读 EXISTS/COUNT(TaskQueryMapper),不 import 并行票的实体/服务,谁先合并都不冲突。
