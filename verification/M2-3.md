## 1. 核销口径(写进 Service javadoc)

- **核销窗口**:配货日 ±48h(`VERIFY_WINDOW_DAYS=2` 天)。取该机器窗口内**全部**导入生成且已确认的出库上架单按 SKU 汇总实上架量(多次导入/多张单聚合,幂等可重算)。
- **差量=带回**:`qty_takeback = max(qty_planned − qty_loaded, 0)`;`takeback_rate = Σ带回/Σ带出` —— 补货 PDCA 核心指标唯一数据生产者(P2-12)。
- 全配→已核销;有差→有差异;窗口内无可匹配单→保持原状态,列表 `overdue=true` 亮黄灯(还有「手动核销」修复口,补导后重扫)。
- 已核销/有差异的单**不重复核销**(重复导入零副作用);核销与导入同事务,失败整体回滚无悬空中间态。
- **FEFO 提示级(M2-7)**:明细行带「仓库最早入库日」= stock_ledger 最早正向流水业务日,tooltip「先出旧货」;完整批次/效期管理记债不做。

## 5. 坑(each)

1. **@ActiveProfiles 会沿继承链累积**:PrekitFlowTest extends RegressionSupport,生效 profiles={test, test-regression, test-prekit},靠"后声明者覆盖同名属性"拿到 vend_test_prekit 数据源——新并行票照抄此模式即可,但别指望子类注解"替换"父类。
2. **核销必须聚合窗口内全部导入单,不能按"本批"匹配**:同机器同日常有多张转移单(多次补货时间戳各成一单),按单匹配会把后到的单算成带回;按 机器×窗口 Σ 后幂等可重算。
3. **已核销单跳过重核**是幂等关键:重复导入 dup 行不生成新单,但若不 guard 状态,verifyAfterImport 会把已核销单重算一遍(数值虽同仍多写 op_log)。
4. **手工转移单入口必须走公开 createDoc**(强制 docSource=手工,P1-5):出库上架自动进预挂单、碰撞检查/负库存拦截全生效;绝不能图省事走 createDocWithSource("导入") 绕开 P0-4。
5. **raw U+0001 控制字符别直接嵌 Java 源码**:分组 key 拼接用了不可见控制符,肉眼/往返编辑极易损坏,已改用可见分隔符 `|`(LocalDate.toString 定长,无歧义)。
6. **浏览器预览面板长页滚动截图会出"stale 帧"**:截图合成器卡旧帧像是页面白屏,console 实际 0 错;导航一次即恢复,验收时先以 read_console/DOM 状态为准再补截图,别误判成前端 bug。
7. Element Plus 表格右缘按钮可能被容器水平裁切(操作列 fixed 未设):p5 列表"标记已执行"在窄视口需横向滚动才可点——详情弹窗内提供了同功能按钮兜底;后续 UI 细修可给操作列加 `fixed="right"`。
