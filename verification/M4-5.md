## 五、给 pdca / 月报票的接口签名

### #7 PDCA 建议起草(pdca 票注入 `IPdcaDraftService` 即用)
```java
package top.aole.vend.modules.ai.domain;

public interface IPdcaDraftService {
    PdcaDraftResult draft(PdcaDraftReq req);   // 实现:MockPdcaDraftService(@Service)
}

// 入参(数字全部 pdca 规则引擎给,AI 不算):
IPdcaDraftService.PdcaDraftReq.builder()
    .bizKey("check:<machineId>:<metric>:<period>")  // idempotent 稳定键
    .metricName("售罄率").actualValue(BigDecimal).targetValue(BigDecimal)
    .scope("4楼售卖机").context("自由文本").force(false).build();

// 出参(一键采纳时 pdca 侧据此建 action_item):
class PdcaDraftResult {
    String measureTitle;                 // → action_item.title
    String measureDetail;                // 措施详述(mock 返回 [MOCK] 前缀)
    List<VerifyMetric> verifyMetrics;    // 验证指标 {name, target, note}
    Integer suggestDueDays;              // 建议期限(默认 14)
    Long llmCallId;                      // 🔬 四件套入口 → GET /v1/ai/transparency/{id}
    boolean cacheHit;                    // 24h 命中
    String model;                        // mock(qwen-plus) / 真模型
}
```
pdca 侧只需:C 指标红灯 → `draft(req)` → 展示 measure/verifyMetrics + 挂 `LlmTransparencyBadge(:callId=llmCallId)` → 用户采纳后 pdca 建 action_item。**本 AI 模块不建 action_item。**

### #5 月报起草(月报票):走同一 `LlmGateway`
```java
// 注入 top.aole.vend.modules.ai.service.LlmGateway
LlmGateway.GatewayResult r = llmGateway.invoke(LlmGateway.LlmTask.builder()
    .scene(AiScenes.MONTHLY)               // 路由键 monthly,默认 kimi-k2(§12.2),256K 长上下文
    .sceneLabel("月度经营分析")
    .bizKey("month:" + period)             // idempotent:同月同日不重调
    .prompt(整月流水+报表拼好的 prompt + "\n草稿:" + 规则汇总草稿)
    .reasoning("规则口径说明").inputDigest(原始数据JSON)
    .confidence(数据完备度).promptFingerprint("monthly-report-v1")
    .fallbackText(规则草稿)                  // 失败降级不断
    .build(), force);
// r.getCall().getOutputText() = 报告正文;r.getCall().getId() 挂 🔬;r.isCacheHit() 是否复用
```
模型切换:设置中心「AI 模型配置」改 `ai.model.monthly` 即可(不写死)。

## 六、坑 each(踩坑记录)

1. **MyBatis-Plus `updateById` 跳过 null 字段**:清空模型路由覆盖时 `setConfigValue(null)+updateById` 写不进 null,旧值残留 → 改为「清覆盖=删行(`deleteById`)」,find 走 is_deleted=0 自然回落默认。(modelRouting 用例先红后绿)
2. **vision 调用与网关落库解耦**:#2 真调用发生在 `visionExtract` 内部,若再走 `LlmGateway.invoke` 会二次对话 → 新增 `LlmGateway.record(task, reply, force)` 只落库不发起对话,复用同一幂等规则。
3. **零外呼断言载体**:`OpenAiCompatLlmService` 加 `AtomicLong requestCount`,真请求前 `incrementAndGet`;`isConfigured()` 前置硬校验,断路时抛异常由 `RoutingLlmService` 提前分流去 mock,永不进外呼分支——测试直接断言计数不变。
4. **NL 安全闸顺序**:去尾分号 → 查残留分号(多语句)→ 注释 → 必须 select 开头 → 写关键字正则 → FROM/JOIN 表名全在白名单 → 无表名拒 → 补 LIMIT。LLM 生成的 SQL 也照过这条链(不信任生成结果)。
5. **白名单视图中文列名**:V1.0.16 视图直接用中文别名(月份/机器/毛利…),问数结果不用再翻译即可给老板看;机器库存视图用 `ROW_NUMBER() OVER(...)` 取每 商品×位置×机器 最新一条流水(MySQL 8.0 窗口函数)。
6. **Browser pane ref→坐标映射失真**:该内置浏览器的 ref 点击固定落到错误坐标、待绑定队列按钮在视口 x=1050(超出 800px 截图区),改用 `javascript_tool` 定位/点击才稳(不影响功能,纯测试工具限制)。
7. **异常侦探真数据量大**:vend_dev 近 7 天数据偏少 → 94 条销量骤变(多为环比下降),规则侧已设「前周≥5 件」防小样本;上线后建议按机器/严重度分页,当前一次性返回全量供驾驶舱卡渲染。
