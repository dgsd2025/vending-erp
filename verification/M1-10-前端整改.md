### 2. P1-2 slot 现量误报(律#1/#3)✅
- **后端(report 只读接口)**:
  - `report/dto/ReportDtos.SlotRow` 加 `estQty / estCapacity / estShared` 三字段,`currentQty` 注释标 stale 禁信任;
  - `report/service/ReportService.machineOverview` 用 `stockService.getMachineStockAll(machineId)`(该机 SKU 推算量 = 最近快照锚点+增量)按 SKU 分组回填:同 SKU 多货道 → 每格给 SKU 级合并量 + `estShared=true`,配色分母 = 同 SKU 货道容量合计。
- **前端**:`MachineDetail.vue` planogram 配色/现量全部改用 `estQty`:
  - `estQty` 为 null 或 **负数(缺快照锚点)→ `uncal` 灰格 + 「— 未校准」,绝不出假红**;
  - `estShared` 且有数 → 格子显 SKU 级量 + 「按品合并」小徽标;
  - 每格 tooltip 写死口径:正常 =「现量 = 该机该 SKU 推算库存(最近后台快照 + 之后增量),非货道传感器实测」;合并 =「该 SKU 绑了本机多条货道,推算量按品合并、无法拆到单格;容量为同 SKU 货道合计」;未校准 =「缺后台快照锚点,导快照/盘点后转正」。
  - 同病同治(审计 #2 整改位置):`MachineSlotTab.vue` 货道抽屉「现量」列不再显示恒 0 的 `slot.current_qty`,改为「看详情页」+ tooltip 指路,页脚口径同步改写。
- **真测**:`/machines/16`(1楼售卖机,机器账 -3143 未校准)planogram 16 格 **红格(bad)= 0**(整改前恒红);DOM 抓取 6 格全部 `cell uncal` + tooltip 口径完整(Playwright 输出留档);API 验证 `estQty/estCapacity/estShared` 正确(01/02 东鹏两道 shared=true,estCap=16=8+8)。
- **截图**:`screenshots/m1-10/p1-2-planogram-no-fake-red.png`
